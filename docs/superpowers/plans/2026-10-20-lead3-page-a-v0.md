# Lead 3 Page A v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` or `superpowers:executing-plans`. Implement one task at a time using TDD and stop at every review gate.

**Goal:** Prove that genuinely converted LiveFrames Hero and CTA sections can coexist as a page-scale composition in the preview application and in a clean external Phoenix application without source-runtime leakage, CSS duplication, page-local bypasses, or public-release implications.

**Architecture:** Page composition remains host-owned. Page A v0 uses a dual proof: an in-repository preview route for composition/browser evidence and a disposable external Phoenix host for clean consumer-boundary evidence. The first tracer renders exactly one Hero and two independent CTA instances.

**Tech Stack:** Elixir, Phoenix 1.8.x, Phoenix LiveView, existing LiveFrames function components, precompiled LiveFrames CSS, ExUnit. Do not add Ash, JavaScript libraries, browser packages, Redis, database infrastructure, or new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-lead3-page-tracer-design.md`.

## Review focus

1. The page must load the LiveFrames stylesheet exactly once despite containing three component instances.
2. CTA A and CTA B must use independent caller data and additive classes; changing one must not affect the other.
3. No unavailable Page A section may be replaced with handwritten copied source markup and then reported as supported.
4. External consumer evidence must come from an application outside the LiveFrames repository/worktrees and must contain no private/source material.
5. Browser evidence must distinguish structural, functional, and visual fidelity rather than converting visual imperfections into functional failures or hiding them.
